# Security policy

## Reporting
Do not file public issues for suspected vulnerabilities. Until a private project security contact is published, report findings to the repository owner through the private channel used to provide this workspace. Do not include exploit details in a public location.

## Scope and handling
The repository is an experimental distribution foundation, not a supported operating system release. Do not test against systems or accounts you do not own or have permission to assess. Experiments must use disposable guests. Never commit credentials, tokens, signing keys, or private user data.

Security findings should include affected revision, environment, reproducible steps, impact, and suggested mitigation. No response-time guarantee is established yet.
